    **resolveQuery method** with this flow (parallels `CatalogIntentDetector.resolveQuery`):
    1. Check context expiry (5min/3turn TTL per Phase 3 pattern)
    2. Detect intent from keyword groups
    3. If not order intent → return `{ type: 'not_order' }`
    4. Extract order number and email from query:
       - Pattern: `#number` or `number` contextually
       - Pattern: `email@*` or "for email" context
    5. If order number found but no email → return `{ type: 'needs_email' }` with prompt
    6. If email found but no order number → return `{ type: 'needs_order_number' }` with prompt
    7. If both found → call `orderService.getOrder(orderId)`
       - If found and email matches → return `{ type: 'order_found' }`
       - If found but email doesn't match → return `{ type: 'email_mismatch' }` per D-16
       - If not found → return `{ type: 'order_not_found' }` per D-15/D-16
    8. Use cross-turn context to accumulate order number and email across turns per D-06
    9. Support conversational multi-turn fallback:
       - "Track my order" → "Sure, what's your order number?" (needs_order_number)
       - "#1234" → "Got it. And what email did you use?" (needs_email)
       - "email@example.com" → full lookup (order_found)

    **Cross-turn context** (same pattern as CatalogIntentDetector):
    ```typescript
    private context: { orderNumber: number; email: string; turnCount: number; timestamp: number } | null = null;
    private readonly CONTEXT_TTL_MS = 300000;
    private readonly MAX_CONTEXT_TURNS = 3;
    ```

    - Email mismatch returns email_mismatch
    - Context expiry clears state
