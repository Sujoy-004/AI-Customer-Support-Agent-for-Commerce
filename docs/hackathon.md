## What We Actually Evaluate

**MANDATORY GATE: Documentation Required** — Submissions without both documents will not be evaluated.

**Required Document 1: Product Document** — What are you building, for whom, and why? Cover: problem, target user, core journey, key product decisions, what you chose NOT to build, tradeoffs. Sharp 2-page doc > 10 pages of filler.

**Required Document 2: Technical Document** — How did you build it, and what happens when things go wrong? Cover: architecture, key decisions, AI/deterministic boundary, failure handling, known limitations.

**Additional Builder Signals:** Decision log (running list of "we considered X, chose Y, because Z"), clean git history with atomic commits.

## Challenge Tracks

**Track 1: AI Shopping Agent** — Replace browse-search-filter-compare loop with conversation. Understand intent, narrow options with reasoning, explain recommendations, support path to purchase.

**Track 2: AI-Assisted Checkout Recovery** — Real-time cart abandonment recovery. Detect friction (price hesitation, shipping confusion, trust gap), resolve before user leaves.

**Track 3: AI Checkout Copilot** — Prevent checkout friction proactively. Explain fees, delivery, bundles, payment tradeoffs alongside checkout flow.

**Track 4: AI Customer Support Agent for Commerce** — Store-native agent handling pre-purchase, policy, order tracking, returns. Grounded in actual store data, not hallucinations. Knows when to escalate.

**Track 5 (Advanced): AI Representation Optimizer** — Merchant-facing tool diagnosing AI readiness. Identifies gaps in FAQ, policies, trust signals; prioritizes improvements; shows how AI perceives the store.
