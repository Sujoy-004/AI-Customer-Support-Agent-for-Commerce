# 🏆 KASPARRO Agentic Commerce Hackathon: Master Details

## 🚀 Track 4: AI Customer Support Agent for Commerce (Focus)
**Goal:** Build a store-native AI agent that handles real customer conversations end-to-end without escalating everything to a human.

### ✅ What a Strong Submission Looks Like:
- **Data Grounding:** Answers product questions grounded in actual store data (No hallucinations).
- **Policy Accuracy:** Explains returns, shipping, and warranty policies accurately.
- **Workflow-First:** Handles order status, tracking, and return initiation as **real workflows**, not just text responses.
- **Graceful Escalation:** Knows when to hand off to a human and does so responsibly.
- **Responsible AI:** Avoids overclaiming and handles uncertainty gracefully.

---

## 📝 Mandatory Deliverables

### 1. Product Document ("The Why")
*A sharp 2-page doc is better than 10 pages of filler.*
- **Problem:** What are you solving and why does it matter?
- **User:** Target user (buyer, merchant, or both) and their current experience.
- **Journey:** What you decided to build and the core user journey.
- **Decisions:** Key product decisions and the reasoning behind each.
- **Scope:** What you chose **NOT** to build and why.
- **Tradeoffs:** Encountered tradeoffs and how you resolved them.

### 2. Technical Document ("The How")
*Focus on what happens when things go wrong.*
- **Architecture:** Components, data flow, and connections.
- **Decisions:** Key implementation decisions and rationale.
- **AI Boundary:** Where does AI end and deterministic code begin?
- **Failure Handling:** What happens when Shopify API is down, or the LLM returns garbage/unexpected input?
- **Limitations:** Known limitations and future improvements.

### 3. Additional Builder Signals
- **Decision Log:** A running list: "We considered X, chose Y, because Z."
- **Git History:** Atomic commits with meaningful messages (Evidence of discipline).
